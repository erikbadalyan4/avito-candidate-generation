# Кандидатогенерация для поиска услуг Авито

Решение задачи первого этапа ранжирования. Для каждого запроса отбирается топ-50 кандидатов из корпуса объявлений.

Метрика на тестовом бенчмарке: Recall@50 = 0.6995

## Структура репозитория

- solution.ipynb - блокнот с валидацией на train и финальным инференсом
- requirements.txt - список зависимостей
- .gitignore - правила исключения временных файлов и данных

## 1. Использованные данные и признаки

Текстовые поля
- Поисковый запрос формируется сложением search_query и параметров search_infm_params_text
- Текст объявления формируется сложением утроенного заголовка item_title_raw, удвоенных параметров item_infm_params_text и описания item_description_raw
- Буква ё заменена на е во всех текстах для устранения расхождений в написании
- Все строки приведены к нижнему регистру

Метаданные
- Категория поиска search_category и объявления item_category_id
- Локация поиска search_location_id и объявления item_location_id

## 2. Модели и алгоритмы

Гибридный двухбашенный поиск

Sparse модель
- TfidfVectorizer с униграммами и биграммами
- Параметр sublinear_tf=True для логарифмического сглаживания частоты слов
- min_df=2
- Словарь содержит 2.78 млн признаков на тестовом корпусе

Dense модель
- Предобученный трансформер cointegrated/rubert-tiny2
- Векторы размерности 312 с L2-нормализацией
- max_seq_length=128

Ранжирование кандидатов
- Скалярное произведение векторов запроса и корпуса
- Множитель локации равен 3.2 при совпадении города
- Множитель категории равен 0.001 при несовпадении
- При search_category == 0 фильтр категории отключается
- Итоговый скор рассчитывается сложением 0.40 от нормированного TF-IDF и 0.60 от нормированного Dense
- Отбор 50 кандидатов выполняется через np.argpartition за линейное время

## 3. Схема валидации

- Выборка из 2448 запросов с группировкой по тексту search_query
- Доля холодных запросов составляет 63.2%
- Доля теплых запросов составляет 36.8%
- Корпус для поиска включает 344 825 товаров из train
- Замеры качества на валидации
  - Базовый TF-IDF дал 0.1221
  - TF-IDF с учетом гео и категории дал 0.5358
  - Плотный поиск Dense дал 0.4774
  - Итоговый гибрид дал 0.7233

## 4. Анализ ошибок

Сквозной поиск без категории
- В тесте 222 запроса имеют search_category == 0
- Исходное условие строгого равенства обнуляло скоры для этих запросов
- Добавление проверки category == 0 подняло Recall@50 на тесте с 0.638 до 0.671

Инъекция истории кликов
- Подстановка исторических кликов из train без привязки к городу ухудшила результат с 0.638 до 0.613 из-за попадания чужих локаций
- В финальном решении оставлен модельный поиск

Сравнение с RRF
- Метод Reciprocal Rank Fusion показал 0.6236 на валидации
- Взвешенное сложение скоров показало 0.6941 за счет сохранения силы текстового сигнала
